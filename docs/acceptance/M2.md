## Notes and decisions

- **Contract tests.** One suite (`tests/contract/media-engine.contract.ts`) runs against the real engine (integration) and the mock (unit). The mock is what UI tests will use from M4, and it cannot silently behave differently from FFmpeg.
- **Port change.** `makeProxy` and `makeThumbnails` take the source `duration` (the app already knows it from import), instead of probing again.
- **Things real files taught us** (now covered by tests): MP4 and MOV share one ffprobe format and differ by brand tag; WMV is reported as `asf`; a JPG is reported as a 0.04 s "video"; MP3 album art is a video stream marked *attached picture*; MP3/AAC report bit depth 0.
- **Bug found by the gate measurement.** Hardware-encoder detection tested a 256×256 frame, which VideoToolbox rejects, so the Mac's working hardware encoder was reported as missing. A regression test now compares detection with a real 1280×720 encode; the tester uses an HD frame. VideoToolbox is now detected on the MacBook.
- **Coverage now includes integration and acceptance tests** (`npm run coverage` runs every suite; CI fetches FFmpeg first), so code exercised only by real FFmpeg counts.
- **Fixture fix.** `-frames:v 1` stopped the whole cover-art MP3 after one frame (1 s instead of 5 s); removed.
- **Hardware encoders seen in CI:** Apple Silicon runner → `h264_videotoolbox`; Intel Mac and Windows runners (virtual machines without a usable GPU) → none, so `libx264` is used. The regression test passes on all three. The teacher's Intel MacBook → `h264_videotoolbox`.
