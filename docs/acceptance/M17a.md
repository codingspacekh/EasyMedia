## Step 12: before the pilot (2026-11-05)

Asked by the maintainer after the 15 papers: the smallest things that make the pilot safer.

| Part | Where | Tests |
|---|---|---|
| **A see-through group is faded as one picture** (the open bug of the M/J/26 Gas trial: overlapping parts looked darker). Its parts are drawn at full strength in a layer, then the layer at the group's opacity: on the stage, in every export and in the web page (an `OffscreenCanvas` layer, reused; Chromium has no canvas layers yet), and in the SVG as one `<g opacity>`. A group of one part, or at 100 %, is drawn as before | `withLayer` in `core/animation/draw.ts`, `adapters/canvas/layers.ts`, `core/animation/svg-export.ts` | 2 unit (draw), 1 unit (SVG), 3 unit (layers), 1 e2e: the stage, the PNG and the SVG are the same half-blue where the circles overlap and where they do not (checked to fail without the fix: 64 levels darker) |
| **P8 exam file names**: File ▸ Candidate Details… (centre number: two letters and three digits; candidate number: four digits, `42` → `0042`; name, for "edited by" text), kept in the preferences; every Save and Export box (video, audio, animation, project files) suggests `<name>_<centre>_<candidate>`, never twice, and replaces the papers' `_ZZ999_9999`. The app's dialogs are wrapped once (`dialogsFor`), so every mode gets it | `core/exam-name.ts`, `app/candidate.ts`, `ui/CandidateDialog.svelte`, File menu | 5 unit, 5 app, 3 UI, 1 menu, 1 e2e (the real save box is asked for `Untitled_KH012_0042.mve`) |
| **P9 Help ▸ Report a Problem…**: a log in the app's data folder (`problems.log`, one JSON line each, the last 300, so it outlives a crash): every unexpected error ("Something went wrong") in Video, Audio, Animation and Learn mode with its first lines of stack, errors in the page, failed requests and jobs (FFmpeg) with their reason, the main process's crashes, the page stopping or freezing, and the menu commands used. The report (version, installed or not, OS, processor, memory, a space to say what happened, the entries in the computer's time) is made by the main process, so it works when the page does not, saved on the Desktop by default and shown in Finder / Explorer. Nothing is sent anywhere | `core/problem-log.ts`, `main/problem-log.ts`, `app/problems.ts` (`unexpected`: one message, defined once), IPC `log:page`, Help menu | 4 unit, 5 main, 4 app, 2 IPC, 1 menu, 1 e2e (a menu command and a page error are in the report after a restart) |

## Decisions (the maintainer, 2026-11-04)

- **Picture on a picture** is made in the picture dialog and saved as a new picture, not as an
  overlay track on the timeline: it is what the paper asks, and keeps the timeline as it is.
- **The pilot is v1.5.0**, after v1.4.0 (M16 + M16b) is tagged once the teacher has checked M16b.
- **The GitHub repo is renamed OneEditor** before the pilot, as the update address is built in.
- **Macs are in the pilot**, signed with the maintainer's own certificate as the gradebook is.
