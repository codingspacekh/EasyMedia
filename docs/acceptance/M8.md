### Split, join and speed for sound clips (teacher's request, 2026-10-16)

Music and voiceover clips now work like video clips: **Split** (timeline bar) cuts the selected sound at the playhead — the first part keeps the fade in, the second the fade out; **Join** puts two parts that still play one after the other back together; **Speed** 0.25×–4× in the audio inspector, pitch kept (`atempo`, as for video clips), and the clip's length on the timeline follows (e.g. 30.00 s ÷ 2 = 15.00 s). The preview plays at the same speed. *Separate sound* now also works for a clip at another speed: the sound keeps the clip's speed. Tests: 7 core, 6 commands, 1 compiler, 1 real FFmpeg (4 s at 2× plays 2 s; mutation check: without `atempo` it fails), 1 preview, 1 project file, 2 UI.

### Why lossy exports now use a bit rate

Until M7, H.264 used constant quality (crf). Its file size depends heavily on the picture (a still title is tiny, a moving clip is large), so no honest estimate is possible. M8 exports at a set bit rate (bits per pixel × quality × a factor for older codecs), so the size shown before export is close: on the moving fixture every preset lands within **0.968–1.020** of the estimate (YouTube MP4 0.983, mobile medium 0.982, mobile small 0.968, DVD 1.020, AVI 0.995, WMV 1.007). A flat picture (a plain title) comes out smaller than estimated. Lossless sizes depend entirely on the picture, so the dialog shows **"up to"** a limit.

## Notes

- **Bug found by the E2E tests (older than M8):** text running past the end of the video made the export longer. In Activity 11d the transitions shortened the storyboard to 38 s, but the credits were still set to 30–40 s, and the file was 40 s with the last frame held. The looped text picture was fed for the text's own length and the overlay ran until its longest input ended. Text pictures are now fed only until the video ends, and text starting after the end is left out. Regression test in `compile-text.test.ts`; the E2E test checks 38 s. (An older unit test had the wrong length written into it.)
- **Mutation checks:** removing the `adelay` or the ducking fails both real-FFmpeg audio tests; doubling the size estimate fails all six size tests.
- **Interpretations:**
  - Book B 11f's Android (medium) is 960 × 720 in Movie Maker. EasyMedia keeps the project's shape: 960 × 540 for a 16:9 project, 960 × 720 for a 4:3 project (Activities 11b–11d).
  - The YouTube preset uses the project size (at most 1080 tall). The book picks 1280 × 720 for a smaller file, which is one choice in *Resolution*.
  - README V16 lists ProRes 422 HQ for MOV, but ProRes is not lossless, so only PNG + PCM is offered as the MOV lossless option.
  - Swim_through is scaled down (5–15 s of a 20 s fixture instead of 15 s + 51 s); the storyboard's structure and times are otherwise the book's.
- **Not built (minor):** the *Mute* and *Edit in Audio mode* buttons of screen 08 (Audio mode is M9; volume 0 or Delete do the same as Mute); the *Save as* box of screen 12 (the native save dialog asks for the name and folder, with the right file type); the Learn-mode glossary comparing all formats (T7, M11). A warning when text runs past the end of the video would help students.
- **Approximate preview:** a browser cannot play louder than 100 %, so sounds above 100 % preview at 100 % (the export uses the real volume).
- **TDD notes:** every unit / UI test was seen failing first, except: the real-FFmpeg audio and format tests were written after the compiler change their unit tests drove (proved by the mutation checks above); and one preset test was changed while implementing (Blu-ray became a separate *best* quality, as README V17's "high bitrate").
