## Performance (N3: an effect on a 3-minute stereo clip in ≤ 3 s)

Measured on the MacBook (Intel i9):

| Effect | Time |
|---|---|
| Noise reduction | 1.75 s |
| Change pitch | 1.15–1.65 s |
| Delay (50 echoes, the most) | 2.1 s (5 echoes: about 0.2 s) |
| Reverb (largest room, a tail) | 1.2 s |
| Graphic EQ | 0.6 s |
| Compressor | 0.5 s |
| High-pass 48 dB / octave | 0.3 s |
| Echo | 0.06 s |

Several needed work to get there: the pitch search on a 4× smaller copy with running totals (4.9 → 1.5 s), the EQ's inner loop without array swaps (2.4 → 0.6 s), the FFT's loops (3.7 → 1.5 s for its share) and windows that overlap by half (noise reduction 3.1 → 1.75 s, which also turned out to remove noise better).

## Notes

- **Design decisions:**
  - **Pitch** is SoundTouch's own method (WSOLA time-stretch) written in TypeScript plus the M8/M9 resampler, not the SoundTouch WASM library of the plan: no WASM build or extra licence. The tests use pure tones; the teacher's listening check decides whether it is good enough on real voice and music — if not, SoundTouch replaces one DSP file. README updated.
  - **The DSP still runs in the page** (no Web Worker): every effect is within N3. The page does not respond during the 0.1–2 s an effect takes; a worker remains the way out if slower laptops need it (M12).
  - **Noise reduction:** a frequency is kept when it is above the noise by the sensitivity in two of three windows in a row (as Audacity's default), kept frequencies lift their neighbours (smoothing), and they are turned down again over 0.05 s. §3.1 (sine + white noise): SNR **+16.9 dB**; noise alone **−11.5 dB** at the default 12 dB.
  - **Reverb keeps the length** unless *Let it ring on* is ticked (as Audacity), because Task 11m adds reverb in the middle of a voice. **Delay** makes the sound longer for its last echoes by default (as Audacity's *Allow duration to change*); untick to keep the length.
  - **Bouncing ball** gaps shrink evenly from the delay time (1, ¾, ½, ¼ of it); reverse grows the same way.
  - The **Compressor's before / after** picture uses the steady-level curve on blocks of the selection (an illustration, labelled as such); Preview plays the real result.
  - **Recording:** no live waveform lane while recording (design screen 15 shows one; the panel shows the time and level instead); no latency compensation for overdubbing (headset microphones are close to in time; to check by ear). The take is mono.
  - **Saving:** Audio mode is saved inside the `.mve`, the teacher's choice: one Save for both modes; each track's sound is an exact 32-bit float WAV in "&lt;project&gt; audio/" (about 21 MB per stereo minute). Undo history is not saved (as Video mode). Files of tracks removed since the last save stay in the folder until it is deleted.
  - **The quit warning covers Video mode too**: it was missing before (only Open and New asked).
  - **Packaging (M12):** the installers must declare `NSMicrophoneUsageDescription` and, with the hardened runtime, the `com.apple.security.device.audio-input` entitlement. In development the Electron app's own declaration is used.
- **Coursebook points for the teacher:**
  - **Book B 11.2.21 "Blu-ray"**: it says a Blu-ray player needs **96 000 Hz**, then sets an MP3 to **96 kbps** (a bit rate). An MP3 cannot be 96 kHz (at most 48 kHz); EasyMedia greys 96 000 Hz out for MP3 and says why. The acceptance test follows the book's steps (constant 96 kbps, so 96 kbps was added to the bit rates) and checks that a 96 kHz WAV / M4A is possible.
  - **Activity 11i "Make a second copy of this clipped track"** is read as a backup copy: the test mutes it, so it is not heard or mixed.
- **Bugs found on the way (fixed):** settings choices spilled out of the dialog; the EQ preset name was cut off; the level meter showed "nothing heard" between words and Start could be pressed before the microphone was open (both found with Chromium's test microphone); an in-range bit rate that is not offered said "at most 320 kbps"; silence was raised in the compressor picture.
- **CI:** one run on macOS Apple Silicon (at `a869398`) timed out in an M4 shell test after 2 minutes; the next runs passed on all three platforms. To watch on the pull request. On Windows x64 (at `429fb9a`) the M9 Book A E2E test failed once: its first check of the undo steps on disk took 4.5 s on the runner, which left no time to look again within Playwright's default 5 s. The app was fine (the step reached the disk); the test now waits up to 30 s, as the spec's other waits do.
- **TDD notes:** every DSP, registry, app, adapter, main-process and UI test was seen failing first (most as a missing module), except: the mock recorder, written together with its contract test (the contract failed first as a missing module); the acceptance tests and E2E specs, written after the code they check — each acceptance group was **mutation-checked** (the effect made to do nothing → the tests fail); one compressor test (silence stays silent) written right after its fix. Three of my own expectations were corrected to the true value after measuring: the low-pass is −13 dB (not −12) two octaves up, from the digital filter's real response; the compressor's quiet part is measured after the 1 s release has let go; noise alone drops 11.5 dB (the test asks 10.5–12.5).
