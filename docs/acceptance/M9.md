## Memory (N4)

Measured on the MacBook with the app's performance report (all Electron processes):

| Session | Start | Peak RAM, first M9 build | Peak RAM, final |
|---|---|---|---|
| Video project (M8 check) | 0.8 s | 309 MB | 309 MB |
| Audio mode, typical (Book B 11j: 90 s + 48 s stereo, one 85 s speed change, play) | 1.0 s | 603–636 MB | **569 MB** ✅ |
| Audio mode, heavy (4.8 min of stereo in 4 tracks, three 85 s speed changes, play) | 0.9 s | 782–805 MB | 748 MB peak, ~650 MB afterwards |

What changed (the teacher chose to do as Audacity):
1. **Undo steps on disk.** Each undo step's sound (the replaced region, a removed track, the stereo before *Mix to mono*) is written to the page's IndexedDB right after the edit and loaded back for Undo / Redo. Steps that can no longer be undone or redone are deleted; leftovers of an earlier session are cleared at start. Small steps stay in memory. If the disk cannot be written the step simply stays in memory; if a saved step has gone missing, Undo says so and changes nothing. (`core/audio/stored.ts`, `UndoStore` port, `adapters/indexeddb/undo-store.ts`.)
2. **Decoded sound no longer passes through the main process** (it reaches the page through a temporary file over `media://`): the main process grows by a one-off ~60 MB instead of ~100 MB per file.
3. **Two leaks found with a heap snapshot**: the History list and the waveform blocks kept old track objects (and so old samples) alive. Both now hold only labels / ids. With 85 s Amplify steps the page grew ~30 MB per step before; now it stays flat (183 → 185 MB over four steps). Regression test: `tests/e2e/audio-memory.spec.ts` (fails with the old History list: +117 MB).

The idle app itself uses about 310 MB; each 90 s stereo track adds about 32 MB of samples. The heavy session's peak comes from short-lived buffers (the mix built for playing, the effect's working copy); streaming playback could lower it later. A check on a real 8 GB Windows laptop is still planned for M12.

## Notes

- **Not built in M9 (decisions for the teacher):**
  - **Saving an Audio mode session** (Audacity's *Save Project*). Not in the M9 plan: the work leaves EasyMedia by *Export audio*. A student who quits without exporting loses the audio edits (there is no warning yet).
  - **Recording** (A14), the level meter of screen 13, and the M10 effects (pitch, echo, delay, reverb, EQ, filters, noise reduction, compressor) — all M10.
  - The *Project rate* box of screen 13 shows the rate but cannot change it (all tracks share the first file's rate; the export dialog chooses the file's rate).
  - Dragging files onto the tracks (P4 is not built for Video mode either); renaming a track (the use case exists, no UI yet); *Edit in Audio mode* from screen 08.
- **Design decisions:**
  - DSP runs in the page, not in a Web Worker as planned: every M9 effect is fast enough (N3) and a worker would copy the samples both ways. The worker comes with M10's heavy effects.
  - Normalise allows a peak above 0 dB, with a clipping warning, because Book A 11.26 asks students to try +2. README A3 says "≤ 0"; the warning keeps the teaching point.
  - A variable bit rate is offered for MP3 only; FFmpeg's AAC encoder has no reliable variable mode.
  - MP3 cannot be 96 kHz (the format allows at most 48 kHz); lower MP3 sample rates limit the bit rate (8 kHz: at most 64 kbps). The dialog adjusts the choice and says why.
  - The *32-bit* WAV is 32-bit float (as Audacity), not 32-bit integer.
  - Fades are straight lines (as Audacity's Fade In / Fade Out).
  - A cut that starts before a track's sound moves what is left to the selection start; a selected track entirely after the selection moves up by its length (the time range is removed from the track).
- **Bugs found by looking at the real app** (screenshots against screens 13, 14, 20): a long track pushed the side panel off the window; waveforms were drawn shifted by the header width (`overflow: hidden` on the lane made it the sticky canvas's scroll box); a mono track's Pan slider was cut off; `fetch()` from the page to `media://` was blocked by CORS. All fixed; the E2E tests and a regression test (CORS header) cover them.
- **Undo on disk tests:** 5 core (`stored.test.ts`), 7 app (`audio-undo-disk.test.ts`, with an in-memory store), the real IndexedDB through the UI (Book A E2E: Undo / Redo of a cut after it went to disk) and the memory regression E2E.
- **TDD notes:** every unit / app test was seen failing first (most as a missing module), except: `core/audio/peaks.ts` (test and code written in one step); the export dialog (`AudioExportDialog.svelte`) and the second UI test file, written after the components (a mutation check on the dialog's rate rule makes its test fail); the E2E specs, written after the UI they drive.
