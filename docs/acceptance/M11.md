## Notes

- **Design decisions:**
  - **The task checker is a third Learn tab** (not in the design screens): a *Task* card for the teacher and a *Check an export* card for the student. Tasks are small JSON files (`.mvetask`) the teacher can share.
  - **The comparison exports 10 s of sound and 5 s of video** (README: 5–10 s), the video no bigger than 1920 × 1080, into the app's own `learn` folder; the files are replaced each time. The lossless video is **AVI with FFV1** (faster and smaller than MOV with PNG); Chromium cannot play it, so one exact frame of it is shown with a note — itself a teaching point (lossless files are for keeping and editing).
  - **Before a video is inspected**, screen 22 shows the export dialog's size estimates for a 40.7 s HD video, with a drawn picture at each resolution stretched to the same size (the design's pixelated pictures).
  - **The visualiser stores sample-and-hold steps** (README T4 "stepped"); the book joins its dots smoothly. Figure 11.23's points between the table's values are read off the figure, so 20 samples catch detail that 10 miss. It starts at 8-bit so the table matches the book; the student moves Resolution down to see the levels.
  - **1 MB = 1 000 000 bytes**, as in the books and the export dialogs.
  - **Dropping a file** on the inspector needed one plain function on `window.mve` (`pathForFile`, Electron's `webUtils.getPathForFile`); nothing else in the app accepts dropped files yet (P4).
- **Bug found and fixed (also affected Video mode exports):** on the MacBook, VideoToolbox refused to encode **426 × 240** ("Cannot create compression session"), so any export at a small custom size failed. An export made with a hardware encoder now carries the software encoder's arguments, and the job queue tries them once if FFmpeg fails (3 queue tests; an integration test with an encoder that does not exist, so it fails the first try on every computer).
- **CI:** two M10 tests timed out under load (5 s): comparing long sample arrays with `toEqual`. They now compare bytes (`tests/helpers/samples.ts`), and the unit tests have 15 s, as the UI tests. An M9 E2E test now waits up to 30 s for undo steps to reach the disk on Windows.
- **TDD notes:** every core, app, queue, probe and UI test was seen failing first (most as a missing module), except: the integration tests with real FFmpeg (`tests/integration/learn/compare.test.ts`) and the E2E specs, written after the code they check; the fallback integration test failed first as intended. The exam-question acceptance test made one glossary entry better: "Sample rate" did not say plainly how the file size changes.
