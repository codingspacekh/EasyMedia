## Notes

- **Mutation checks:** shifting the preview text by 5 px made the ≤ 2 px test fail (5 px measured); switching off the fly-in in the export made Task 11a fail (16 changed pixels instead of > 2000). The tests are meaningful.
- **Bugs found by the tests:**
  1. In the real browser a `<select>` inside its `<label>` is named with its chosen option too ("Font Inter (sans-serif)"), so screen readers read a confusing name. The inspector's controls now have explicit accessible names.
  2. The first version of "numbered copy" stripped trailing digits from file names (`photo_3764x3092.jpg` → `photo_3764x1.jpg`). Now the engine always writes the first free `name1`, `name2`… beside the original, and the page no longer chooses the output path at all (safer).
  3. The test PNGs made with FFmpeg's `drawbox` were fully transparent (it does not set alpha); the real-FFmpeg text tests now pad a white block onto a transparent frame.
  4. **Fragile check found on Windows CI:** the 11.10 test looked for yellow in a frame shrunk to 16 × 9, where thin 36 px words are averaged away (65 vs a limit of 60 on the Mac, just under on Windows). It now counts yellow pixels at full size (25 000+ against a limit of 2 000; none in the source clip). The app was right; the test was too tight.
- **Security:** text pictures are written only into the app's own folder by plain name; `media:resizeCrop` takes numbers only (main checks them and builds the filter) and only for pictures the app opened.
- **TDD notes:** the IPC test "crops only pictures the app has opened" was written after the check it tests, so it passed at once; it asserts the refusal and was kept.
- Title slides whose background is a video play it silently from its start (preview and export agree).
- **Windows-laptop performance check:** skipped by the teacher (M5); remains in M12.
