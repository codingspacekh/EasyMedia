## Notes and decisions

- **Undo design.** Projects are immutable; every command returns a new project. Undo restores the previous project exactly, so commands need no hand-written undo. The key property — *no command changes the project it is given* — is tested by deep-freezing the project before applying each of the 13 commands. ARCHITECTURE §3 (P4) and §7.2 updated.
- **Task 11d assumption.** The coursebook does not state the length of `Fish_Eagle.mp4`. The scenario assumes **8.00 s**, giving the **40.70 s** total. `Lake_Naivasha.mp4` is assumed to be 20 s.
- **Join.** "Join" merges neighbouring parts that came from splitting the same clip. Placing different clips one after another is already "splicing" (Book B's definition); Book A's grouping of separate clips is not modelled.
- **Times** are kept at full precision internally and rounded to 0.01 s only when shown or typed, so speed changes (e.g. 6.3 s at 1.5× = 4.2 s) do not build up rounding errors.
- **Process slip caught by the gate.** A few command rules were written ahead of their tests; the `app/` branch-coverage threshold (85 %) failed the gate. Behaviour tests were added for each rule before continuing.
- **Mutation check.** Breaking the speed rule in `timeline.ts` made the Task 11d test fail (42.80 s instead of 40.70 s), confirming the acceptance test is meaningful.
