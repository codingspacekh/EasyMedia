## How to check on a Windows laptop

1. On the Mac: `gh workflow run app-bundle.yml --ref dev`, wait about 5 minutes, then `gh run download --name EasyMedia-windows --dir EasyMedia-windows`.
2. Copy the `EasyMedia-windows` folder to the laptop (USB stick or shared drive).
3. Close other programs, then double-click **`Measure performance.bat`**. If Windows SmartScreen appears: **More info → Run anyway**.
4. In EasyMedia: **Import** a coursebook video, wait for **Ready**, click **Add**, press **Play**, then **Export**.
5. Close EasyMedia. Bring back **`performance-report.json`** and fill in the table above.

## Notes

- **Bugs found by the tests:**
  1. A shared bundle chunk broke the sandboxed preload (`window.mve` missing) — caught by the E2E security test; the preload is now built as one self-contained file.
  2. **The preview covered the toolbar in short windows** (its 16:9 frame overflowed upwards) — caught on the Apple Silicon CI runner, invisible on a large screen. Fixed with container-sized layout; regression test at the minimum window size 1100 × 700.
  3. **E2E never started on Windows** — the app path ended with a backslash, which on Windows escapes the closing quote of a command-line argument. Test helper fixed.
- **Plan correction:** the M4 manual check "export Book B Task 11b through the UI" needs trim and remove-sound controls, which are M5 scope; it is moved to the M5 gate.
- **TDD slip:** `previewAt` and its tests were written in one step, so the test was never seen failing first. The tests check real behaviour; noted for honesty.
- Electron start-up files (`src/main/index.ts`, `services.ts`, `perf.ts`, `src/preload/index.ts`, `src/ui/main.ts`) run only inside the real app; they are covered by the E2E tests and excluded from unit coverage.
